# Codex Task fan-out cache measurement, 2026-10-24

Owner: [ISSUE-029](../../ISSUE-029.md).

## Setup

- Source CLI `bun packages/coding-agent/src/cli.ts -p --model openai-codex/gpt-6-luna` from `personal@837b153e93`; patched variants ran from a throwaway worktree.
- The Main agent spawned one `task` Child, waited for it, then spawned four `task` Children in one call and waited again.
- Each run used a fresh cwd whose `.omp/SYSTEM.template.md` prepends a unique marker to the user template, so only same-run siblings share the marker prefix.
- Children ran `gpt-6-luna`; first-request prompts were about 20.4k tokens.
- Every run shares about 6,400 cached tokens in front of the marker; a full hit reads 18,944 cached tokens, which requires the marker prefix.
- Metric: full hits among the four followers of each run, from the first assistant `usage` in each Child session file.
- Excluded followers failed with `Codex error event: Codex is at capacity`; this hit unpatched and patched WebSocket variants alike.

## Patch variants

- Header affinity: `createCodexRequestContext` sets `affinitySessionId` from `parentSessionId`, else from a `promptCacheKey` differing from `sessionId`.
- Sibling key: `providers/openai-codex.kdl` sets `task-sibling-prompt-cache #true`, so Children send `prompt_cache_key = <parentKey>:task`.
- `FANOUT_NO_AFFINITY` kept the sibling key but disabled header affinity; `FANOUT_NO_PREWARM` skipped `prewarmOpenAICodexResponses`; `PI_CODEX_WEBSOCKET=0` forced SSE.

| Variant | Transport | Full hits |

| Shared key as session headers | WebSocket with prewarm | 1/16 |
| Shared key as session headers | SSE | 24/24 |
| Shared key as session headers | WebSocket without prewarm | 24/24 |

## Interpretation

- [O] Session headers, not `prompt_cache_key`, route sibling cache hits on `openai-codex`.
- [S] `prewarmOpenAICodexResponses` opens the WebSocket with headers built from `createCodexCompatibilityIdentity`, which carries no `affinitySessionId`; later requests reuse that socket, so request-level header affinity has no effect on the default WebSocket path.
- [O] Header sharing caused no request failures in any variant.
